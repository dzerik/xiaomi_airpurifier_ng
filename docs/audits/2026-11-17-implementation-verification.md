## Критерии приёмки

1. Настоящие Device/Status и codec покрывают все семейства, enum, RPM, 1C, JSQ001 и формы ответов MIoT.
2. Каждая поддерживаемая модель имеет профиль; неизвестные модели отклоняются.
3. Проверены границы скорости, ноль, включение с параметрами и ручные/автоматические режимы.
4. Основная сущность и number используют единый путь влажности, диапазоны и prerequisites.
5. Общий замок сериализует команды, polling и executor после отмены; частичный отказ виден вызывающему коду и вызывает refresh вне замка.
6. Неверный MAC не меняет entry. Реальный registry сохраняет одно устройство при late info; entity IDs сохраняются при повторном создании сущностей.
7. Минимальная, текущая и серверная HA проверены; ограничения внешнего CI указаны выше.
8. README обоих языков содержит требования, миграцию пресетов, ограничения и актуальные команды разработки.

## Решения при реализации

- Native выполнение в текущей ветке было явно согласовано; дополнительный worktree не создавался. Изменения не объединяются с main и не публикуются без отдельного запроса.
- Airdog требует комбинированную команду режима/скорости; AirFresh имеет собственные диапазоны. Профили расширены по реальному API драйверов. Риск: firmware может отличаться от библиотечного контракта.
- `uv compile` получает точную версию Python 3.14.2: сокращённое `3.14` означает также несовместимую 3.14.0. Риск: минимальная версия в инструкции должна оставаться синхронной с HA.
- UI-метаданные и старые вызовы `_try_command` перенесены вместе с платформами в задаче 4. Это последовательность реализации, итогового обходного пути к executor нет.
- HA отображает три уровня как 33/66/100%, поэтому исправлена опечатка 67% в дизайне. Риск: автоматизациям с буквальным прежним значением нужна миграция.
- Старые проверки приватных флагов/копий таблиц заменены проверками публичного поведения и точных пакетов; сохранившиеся полезные регрессии продолжают выполняться. Риск: внутренние структуры больше не фиксируются тестами намеренно.
- Нормализация MAC и registry aliases вынесены в `identity.py`. Если у старой host-based entry никогда не было известного MAC, прежнюю физическую идентичность доказать нельзя; при наличии используется MAC из registry.
- Процент вычисляется свойством сущности через профиль, исходная скорость сохраняется в диагностике. Потребители внутренних coordinator data должны использовать преобразование профиля.
- Manifest использует HA-совместимые диапазоны, поскольку Hassfest запрещает strict pins общих с Core пакетов. Тестовые locks фиксируют miio 0.5.12 и обе версии Construct. Риск: обновление разрешённых патчей требует повторных регрессий.
- Угол P15/P18 скрыт, пока драйвер не поддерживает эти aliases. Возможность не выдумывается; рабочая аппаратная функция может оставаться недоступной до поддержки транспорта.

## Границы проверки и развёртывание
